# Four complete-family MIPs at 1,000 tasks

> Public copy. Administrative sentences about project approval and cluster job handling were removed; the technical protocol is unchanged. The SHA-256 of the file as run is listed in `cluster_snapshot_code.manifest.json`.

Written 12 October 2026, after the LP scaling study. This is an additive diagnostic study, with one run per input and no changes to earlier code, data, outcomes, or acceptance flags.

- Fixed cases: `diag2_L04_n1000_s0`, `diag2_L04_n1000_s1`, `diag2_L15_n1000_s0`, `diag2_L15_n1000_s1`. Copy the exact `instance.json` from repeat 0 of the completed LP study. Verify its canonical payload hash, then require the frozen builder to reproduce every serialized field exactly before timing. The LP records contain every model input used here (including net demand), but not its separate demand/solar decomposition; the existing frozen builder also preserves that decomposition.
- Family: all source-to-sink paths of the same pruned lossless DP graph, plus every real original singleton seed. Truck grid step is 50 kWh and its effective block rate is 150 kWh; singleton seeds and continuous aggregate stationary storage retain the physical 175 kWh block rate. Trucks start and finish full; stationary storage is periodic. Every truck serves at least one task. Preserve parallel task arcs and all original coupled rows. Generation and aggregate charging are uncapped.
- Integer variables: every arc flow, DAG fleet flow, singleton count, and stationary battery count. Other aggregate energy variables remain continuous. No artificial routes. No arbitrary fleet cap; existing graph bounds follow from task coverage and the served-task state.
- One fresh Gurobi 12.0.3 process per case on `lisbeth`, one allocated CPU, one solver/math thread, seed 0, automatic MIP/root method (`Method=-1`), relative MIP gap 1e-6, absolute MIP gap 1e-10, feasibility/optimality/integrality tolerances 1e-8. Defaults otherwise. No external incumbent, LP basis, prior objective cutoff, or warm start. Native internal heuristics remain at defaults.
- Budget: 1,800 seconds includes graph and seed construction, matrix conversion, Gurobi environment/model construction, and optimization. Subtract elapsed construction before setting native `TimeLimit`. Imports, exact input verification and initial serialization precede the timer. Native solver time limits can overshoot slightly; record actual elapsed time. Final raw incumbent serialization and independent numerical replay follow the stop timestamp and are reported separately. A fresh-process watchdog permits another 600 seconds for diagnostics, kills the entire worker process group if exceeded, and reports an external failure rather than an optimization-time censor.
- Evidence: immutable input, environment/CPU/affinity, source and input hashes, native solver log, bounded progress trace, status, incumbent if any, lower bound, native relative gap, node/iteration counts, graph/model sizes, peak process RSS and solver memory, raw compressed primal vector, sparse matrix feasibility/objective/integrality check at absolute 1e-6, and physical route/BESS replay. Independent read-only replay of saved results follows. A numerical replay pass validates the incumbent; global optimality is only the native solver's bound/gap claim to its stated tolerances.
- Keep every outcome, including no incumbent, time limit, numerical failure, and external timeout. For positive objective incumbents report `(incumbent - native_bound)/abs(incumbent)` and compare the native bound with the previously validated LP bound. Do not label a timed-out native MIP optimal, equate a restricted heuristic gap with an integrality gap, or infer general instance hardness from these four cases. These MIPs address whether the earlier difficulty persists with the complete implemented integer family. This does not establish equivalence to an unrestricted continuous-energy integer model.

Implementation: `direct_mip_1000.py` (a new file). Preflight constructs an actual saved 1,000-task input without optimizing.

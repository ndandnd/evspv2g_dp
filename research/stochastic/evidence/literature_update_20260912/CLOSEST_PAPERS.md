# Closest application and computational references, beyond Ricard/Lodi

Audited 12 September 2026. This is a bounded update to REVIEW.md, not a systematic review. **Najafi et al. (2025) is the strongest newly identified structural overlap.** It already combines endogenous bus duties, common charging decisions, stationary storage sizing and uncertain PV. Accordingly, neither integrated duties/storage planning nor adding renewable uncertainty is independently a defensible novelty claim. Baldua's `csp-res` remains the most immediately useful implementation reference; Terada's previously missing public implementation is now identified.

Our comparison target commits mandatory timed truck duties **and their complete energy profiles**, integer BESS quantity and shared initial BESS energy before weather; continuous BESS/fossil dispatch then sees the complete day. It uses an isolated microgrid, aggregate charging limits, root column generation and a finite-pool MIP. It does not allow scenario-adaptive truck charging. Rankings below are judgments about this target, not paper quality. A = application/structural relevance; M = algorithm/reference-implementation relevance; 1 is closest.

The useful remaining research question is narrower: **how mandatory precommitted mobile-storage duties and integer stationary-storage investment interact under common weather uncertainty in an isolated grid, including when V2G substitutes for or complements BESS.** Establish this through matched technology/commitment experiments, not a claim to invent stochastic integrated scheduling. Najafi requires explicit discussion in the manuscript. None of these papers supplies a verified drop-in implementation of our stochastic pricing problem.

## Published code and a small reuse test

**Baldua / csp-res:** pinned commit `615817bc86cb6a7d5e96efd1532ec45b7e9ee2a2`; [source tree](https://github.com/transnetlab/csp-res/tree/615817bc86cb6a7d5e96efd1532ec45b7e9ee2a2). The repository contains an MIT license, pinned requirements including CPLEX 22.1.1.0, NumPy 1.26.4 and pandas 2.2.1, and Durham GTFS/solar/energy/rotation inputs in `Durham_2.1k.zip`. Archive contents were listed, not deserialized. Canberra inputs were not found in this checkout.

The reusable pieces are explicit [first-stage and scenario constraint builders](https://github.com/transnetlab/csp-res/blob/615817bc86cb6a7d5e96efd1532ec45b7e9ee2a2/csp.py), particularly `add_first_stage_variables` and `add_solar_battery_level_and_max_energy_level_constraints`. Their partition annotations put capacities/shared boundary energy in partition 0 and dispatch in scenario partitions. This is CPLEX's built-in Benders, **not a solver-independent cut-generation library**. The driver mixes building, scaling, solving and output; it explicitly forces LP at line 875. Its `variable_type` argument must therefore not be treated as proof of integer-planning support. Global parameters, relative paths and nested dictionaries need adapters; the scenario builder averages hourly irradiance and reads/writes pickle files. No automated model-correctness suite was identified; `stability_test_lp.py` is scaling support.

**Proposed first reuse check, not executed:** construct one location, two fixed bus rotations, 8 periods and two solar profiles as plain in-memory data. Adapt only the constraint/partition pattern into a scratch model; verify extensive-form and Benders objectives within `1e-6` relative tolerance, energy-balance residuals and identical shared initial energy. Then fix one of our truck-profile pools and compare its continuous dispatch objective against our existing evaluator. Keep integer BESS and duty selection in our own model. This isolates reusable decomposition mechanics before any full-network reproduction.

**Terada / ev-scheduler:** pinned commit `2253383a761305fd807afab7d59b6b342bbb3d6b`; [actual model](https://github.com/TeradaZenichi/ev-scheduler/blob/2253383a761305fd807afab7d59b6b342bbb3d6b/linear_model.py) and [JSON inputs](https://github.com/TeradaZenichi/ev-scheduler/tree/2253383a761305fd807afab7d59b6b342bbb3d6b/data). It uses Pyomo/Gurobi and runs construction, solve and plotting at module scope. README setup needs repair: root `requirements.txt` is absent (an archival copy exists), the stated `linearmodel.py` filename differs from `linear_model.py`, and README's 10% gap differs from the current model's 1%. README claims MIT but its linked LICENSE file is absent. Treat reuse licensing as unresolved. Reimplementing its documented arrival-window/contingency comparison from equations is more practical than importing this script into our solver. JSON scenario inputs and energy-balance structure are useful comparison material; a 3-EV, 2-scenario scratch check should verify pre-outage control consistency, beyond matching SoC.

For Najafi, Yetkin, Son and Zheng, this bounded search did not verify downloadable author implementations or complete runnable datasets. That does not imply they do not exist. Najafi reports GAMS/CPLEX; Yetkin describes modified MATPOWER cases, which are not themselves the exact author model.

## Provenance and access limits

Both code repositories were cloned under this directory's `vendor/` and inspected as text; no external code, pickle inputs or optimization pipelines were executed. The Najafi publisher PDF was retrieved from the Chalmers institutional endpoint and visually checked alongside the DTU version-of-record text; formulation citations use printed page numbers. Yetkin's publisher full formulation was accessible; its separate arXiv v4 is dated August 2026, so journal/preprint equivalence is not assumed. Baldua is labeled preprint because this search did not verify a journal version. Son's SSRN download returned an access error; Son and Zheng claims remain limited to publisher/author previews. Terada's code is direct author evidence, not proof that every detail matches the published article.

## Actual data inspection and readiness

The [README](https://github.com/learicard/evsp-policy-battery/blob/8562206fe1349445f1d8e7b7b6ebd67960ab9bda/README.md) documents the input schemas and a 300 kWh bus battery. I also parsed all CSVs independently with Python's standard library:

- Fifteen trip sets: I1 contains 59–63 trips, I2 153–156, I3 243–252. Every trip's probability-vector length matches its inclusive integer support, and every probability vector sums to one at the stored precision. Example [raw trip file](https://github.com/learicard/evsp-policy-battery/blob/8562206fe1349445f1d8e7b7b6ebd67960ab9bda/instances/I1/trips_1.csv).
- [Results](https://github.com/learicard/evsp-policy-battery/blob/8562206fe1349445f1d8e7b7b6ebd67960ab9bda/results/all_results.csv): 390 records: 330 stochastic, 30 optimistic, 30 worst-case. Fields include UB/LB, reported gap, buses, branching nodes, and CPU times. No actual chosen schedules, column pools, simulator, or random seeds accompany these records, so they support result comparison, not independent feasibility verification.
- Parser details: actual I3 location filename is [`I3_locations.csv`](https://github.com/learicard/evsp-policy-battery/blob/8562206fe1349445f1d8e7b7b6ebd67960ab9bda/instances/I3/I3_locations.csv), unlike README's `locations.csv`; the results file has a UTF-8 BOM; [deadhead dictionaries](https://github.com/learicard/evsp-policy-battery/blob/8562206fe1349445f1d8e7b7b6ebd67960ab9bda/instances/shared/travel_data.csv) mix integer and string keys, including `0` and `'0'`. A loader should use `utf-8-sig`, `ast.literal_eval`, normalize keys and validate duplicate values. These are small adaptation issues, not failed model tests.

**Readiness:** data loading is straightforward; rerunning the author's algorithm is not possible from the released snapshot alone. The EJOR paper reports **GENCOL 4.5 and CPLEX 22.1**, with experiments on Linux, 16 Xeon processors and 125 GB RAM. It supplies no public Python/Gurobi package through this repository. [Publisher, Section 4](https://doi.org/10.1016/j.ejor.2026.05.046).

## Actionable fit to our model (assessment)

Our reference architecture is the supplied scope: Python/Gurobi root column generation followed by a frozen-pool MIP; fixed truck profiles; shared integer BESS size and initial SoC; continuous full-day weather recourse; causal BESS-dispatch evaluation.

| Candidate | Adaptation cost / decision |
|---|---|
| Benchmark inputs and result schema | **Low** to load into an isolated experiment, **high** to compare objectives directly: bus scheduling, depot and charger capacity, and bus battery consumption differ from fixed truck/V2G profiles and shared stationary storage. Use only for a clearly separate EVSP comparator. |
| Pricing distribution state and dominance | **High**: would require our own implementation and proof. The paper's discretized vehicle SoC and per-trip distributions do not automatically extend to continuous full-day weather trajectories and coupled BESS recourse. No compiled or Python pricing routine was available to transplant. |
| Chance-constraint idea | **Medium/high modeling work**. Joint daily compliance is a useful evaluation target, but a schedule-factorized probability cannot be carried over without checking dependence: common weather and a shared BESS couple our columns. Scenario-wise aggregation with a shared controller requires fresh derivation. |
| Diving / arc fixing | **Medium/high**, optional later experiment. It requires node-specific pricing and branch restrictions honored by every generated column. Running a Gurobi MIP on the frozen root pool remains a restricted-pool MIP, even though Gurobi branches internally. It does not become branch-and-price. A full exact B&P claim additionally needs complete branching and valid bounds with pricing throughout the tree. A root LP is a certified full-master bound only with pricing closure or another valid bound certificate; the restricted MIP's solver gap applies only to that pool. |
| Recourse and evaluation ideas | **Useful now as a specification check**: keep observation times explicit, compare each first-stage design on the same full-day held-out weather trajectories, and evaluate causal dispatch using only information available at each decision. An unrestricted full-day recourse LP can be a perfect-information benchmark; the recourse talk does not establish that it is a causal operating policy. |

Recommended immediate reuse: retain the licensed dataset as an auditable external benchmark, adopt clear reporting of the root LP bound versus frozen-pool MIP result, and reimplement only a narrowly justified probability/evaluation component after matching assumptions. Do not schedule a solver migration based on the repository name. Obtaining the missing GENCOL application source, build/runtime details and solution schedules would be the next evidence needed for an implementation-level feasibility assessment.
